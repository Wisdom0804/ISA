# ISA 需求分析

## 1. 文档定位

本文定义 ISA 的已确认产品需求，作为后续设计、开发和验收的依据，不表示相关功能已经实现或通过验证。

产品使用 Python 生态实现，为《明日方舟》集成战略玩法中的《黑流树海》模式提供桌面辅助，主要面向个人使用，并计划开源。

本文不指定 GUI 框架、画面捕获方式、识别算法、模型调用框架或存储方案。具体技术方案及兼容性需要在设计和开发中验证。

## 2. 产品目标与边界

### 2.1 核心目标

助手根据本局目标、当前楼层完整地图、局内资源、队伍能力和用户风险偏好，持续推荐行动路径，回答以下问题：

- 接下来应该经过哪些节点？
- 这段路线的目的是什么，如何帮助达成本局目标？
- 为获得预期收益，需要提前准备什么资源、满足什么条件？
- 到哪个节点后需要根据实际结果重新判断？

支持《黑流树海》的全部难度，识别当前难度，并将其用于战斗风险评估和路线规划。

### 2.2 运行与操作边界

- 游戏运行于《明日方舟》官方 PC 客户端。
- 游戏使用无边框或窗口化模式是必要运行条件。
- 助手通过画面识别获取信息，允许用户手动修正。
- 助手使用独立置顶、可拖动的悬浮窗显示建议和接收输入。
- 助手无法操作游戏，不能代替用户点击节点、选择事件选项或执行战斗操作。
- 自然语言命令只作用于助手自身。
- 透明效果、点击穿透和快捷隐藏不作为本文已确认的功能要求。

## 3. 本局目标

### 3.1 目标结构

本局目标仅包含以下两个结构化字段，不包含收藏品获取要求。

| 字段 | 含义 | 为空时的含义 |
| --- | --- | --- |
| 结局 | 指定达成的结局 | 不限制结局 |
| 分队 | 指定使用的分队 | 不限制分队 |

指定分队与指定结局允许组合，不设置二者之间的目标冲突处理。两个字段都为空时，目标为使用任意分队、达成任意结局通关。

风险偏好属于个性化设置，不属于目标结构化解析字段。收藏品仍属于影响规划的局内状态。

### 3.2 目标设置与确认

- 开局支持直接选择预设选项，也支持输入自然语言进行目标识别。
- 自然语言只解析为上述目标字段，无法表达的内容明确提示未纳入目标。
- 空字段表示不限制，不阻止开始规划。
- 解析结果必须先展示给用户，确认后才能作为规划依据。
- 结果确认界面仅允许通过选项调整，不提供自然语言编辑目标的方式。
- 局内允许主动修改目标，仍通过结构化选项调整和确认；确认后重新规划。

### 3.3 目标异常处理

- 指定分队与识别到的实际分队不一致时，暂停推荐，提示核对，并允许重新扫描或修改本局目标。
- 有充分依据确认目标无法达成时，说明原因，等待用户选择更换目标、继续游玩或结束本局，不自动切换目标。
- 目标成功率降低不等于目标已无法达成。

## 4. 路线规划与建议

### 4.1 规划范围

- 围绕整局目标持续规划，结合实际进展调整策略。
- 每次整体路径推荐以当前楼层的完整地图为基础，不要求预先获得后续楼层地图。
- 当前楼层地图不完整时，通过悬浮窗提示用户展示缺失区域，供助手识别补全。
- 推荐路径可以只覆盖一段路线，到指定节点后根据新增信息重新判断，不要求一次规划至楼层终点。
- 对尚未出现的地图和随机结果，只能表达条件策略，不能作为已知事实。

### 4.2 推荐呈现

- 默认明确推荐一条路径。
- 只有下一节点候选方案的推荐程度接近时，才提供备选，并说明取舍。
- 默认解释聚焦路径目的、与本局目标的关系、预期收益及资源准备。
- 区分确定收益与随机机会，说明收益成立的前提。
- 路径止于需要重新判断的节点时，说明在该处重新判断的原因。
- 具体机制依据、攻略来源在用户追问时提供，不作为默认解释的主要内容。

### 4.3 策略要点

涉及局内操作时，以策略要点为主，不要求逐步战斗操作攻略。例如推荐进入商店时，解释期望补足什么、提前预留哪些资源，以及预期收益未出现时如何取舍。

### 4.4 战斗风险

- 以队伍评估为主要依据，结合当前难度、局内队伍实际状态、增益和关卡要求判断战斗风险。
- 账号干员资料用于判断后续招募和补强是否可行。
- 用户可以配置长期生效的特殊战斗节点列表，列表内节点视为难度极大。
- 特殊节点的高风险设置不等于禁止进入；仍推荐经过时，需要解释原因和风险。

## 5. 识别、状态更新与暂停

### 5.1 信息范围

识别和维护与规划有关的信息，包括当前难度、分队、当前楼层完整地图、当前位置、可选节点、资源、队伍、收藏品及其他局内效果。具体字段依据游戏机制和规划需要在后续设计中细化。

识别以自动获取为主，允许用户手动修正。

### 5.2 更新时机

重点识别地图、资源与相关信息、队伍等关键变化，再根据变化更新建议，不因节点内部的每次画面变化持续分析。

- 地图或可选路径变化后，补全相关信息并重新分析。
- 资源、队伍、收藏品或重要条件发生影响规划的变化后，更新状态和建议。
- 战斗过程中不持续识别和分析战斗操作，战斗结束后读取整体资源及状态变化。
- 不期而遇等包含选项的节点，支持用户主动提问，了解选项差异及对目标的影响。

### 5.3 暂停规则

- 识别和分析期间暂停推荐，包括地图补全、重新扫描和重新规划。
- 悬浮窗明确显示当前识别、等待补充或分析状态，已有建议不能继续作为有效推荐呈现。
- 发现资源状态与实际不符，或确认信息不足时，暂停推荐，提示用户展示资源信息供重新扫描。
- 重新扫描并完成分析后恢复推荐；问题未解决时保持暂停。

### 5.4 本局重要信息

- 正常跟随游玩过程中，记录会影响后续规划的重要事实，例如已完成的目标前置条件和关键事件选择。
- 已记录的重要信息不因当前画面不再展示而遗忘。
- 中途接入时，无法从画面还原的历史信息默认不记录，不主动要求逐项补充；未记录表示未知，不能推定为未发生。
- 用户在提问中明确提供实际发生的局内事实时，直接补充或修正记录，无需再次确认，并重新分析。
- 假设性问题不修改实际局内状态。

## 6. 悬浮窗与自然语言交互

悬浮窗承担建议展示、识别补全提示、暂停原因提示和自然语言输入。

| 输入类型 | 行为 |
| --- | --- |
| 路线解释 | 解释推荐路径的目的及选择原因 |
| 方案比较 | 比较其他路线或节点选项的差异 |
| 依据追问 | 提供具体机制依据及攻略来源 |
| 助手命令 | 触发重新扫描、重新分析、暂停推荐等助手操作 |
| 事实补充 | 按明确提供的事实更新本局状态并重新分析 |

自然语言输入不能绕过目标选项确认流程，也不能修改局内锁定的风险偏好。

## 7. 个性化设置

### 7.1 风险偏好

- 提供稳重、均衡、激进三档，长期保存。
- 稳重更重视降低失败风险；均衡兼顾风险与收益；激进更愿意承担风险以争取收益或目标机会。
- 风险偏好仅能在局外配置，开局后整局锁定。
- 助手根据局势调整具体路线，不自行修改用户风险偏好。
- 各档位的具体评估规则需要结合游戏机制与案例验证，本文不规定未经验证的权重和数值。

### 7.2 特殊战斗节点

用户维护长期生效的特殊战斗节点列表，后续各局均将列表内节点视为难度极大，用户可修改列表。

### 7.3 账号干员资料

- 保存干员持有及养成情况，供后续招募和队伍补强评估使用。
- 通过展示游戏内干员资料进行扫描录入，允许手动修正。
- 首次进入应用仅提供一次录入引导，允许跳过，跳过后不再强制要求；用户可主动进入设置录入。
- 用户主动发起重新扫描；只更新已识别内容，保留其余已有资料。
- 局内发现实际干员信息与保存资料不一致时，提示核对，经用户确认后更新账号资料。

未完成资料录入时，按拥有全部干员处理，默认养成为：

| 项目 | 默认值 |
| --- | --- |
| 精英阶段 | 精英二 |
| 等级 | 60 级 |
| 潜能 | 无额外潜能 |
| 技能 | 专精三 |
| 模组 | 一级 |

超出某干员实际支持范围的养成项按其支持的上限处理；没有模组的干员不计模组。上述数据是账号可用干员的默认假设，局内已招募干员仍按识别结果及用户修正判断实际状态。

## 8. 对局管理与历史记录

### 8.1 创建与结束

- 用户点击“开始新一局”创建记录，不自动创建新对局。
- 支持从游戏中途接入，确认目标后直接提示展示资源供扫描，并补全当前楼层地图。
- 助手允许自动识别本局结束，也允许用户手动结束。

### 8.2 保存与查看

- 每局保存最新目标、最新局内状态及影响后续规划的重要事实。
- 历史对局支持查看最新目标和最新局内状态。
- 不要求历史界面展示状态变化过程、过去的建议路径、分析进度或暂停原因。

### 8.3 关闭与恢复

- 关闭应用后保留对局记录。
- 重启后，保存的可变状态视为待校验，不能直接用于恢复推荐。
- 提示用户展示当前资源供重新扫描，并补全必要信息；完成校验和分析后再恢复推荐。
- 此前已记录的重要历史事实继续保留，不因重新扫描而清空。

## 9. AI 服务与知识资料

### 9.1 服务配置与响应

- 允许联网使用 AI 服务完成目标解析、路线分析及追问回答。
- 用户自行配置模型厂商、API Key 和模型。
- 为支持的厂商配置适配器，将响应转换为约定的结构化信息；格式解析属于开发职责，不转化为用户操作要求。
- 模型建议允许直接展示，不增加额外的建议内容审查流程。
- 调用或处理失败时允许自动重试，最多重试 5 次；重试期间暂停推荐，重试仍失败则保持暂停，显示失败原因并允许手动重新发起。

### 9.2 知识库

- 建立覆盖所支持玩法、全部难度及规划所需机制的知识资料，作为正常提供建议的前提。
- 开发过程中遇到资料缺失，直接提示缺少资料，不编造缺失内容。
- 通过独立更新知识库资料同步游戏内容变化，不要求同时更新应用版本。
- 应用版本更新主要侧重功能更新。

## 10. 质量与设计约束

- 当前以建议质量为优先，不设置具体响应时间上限；识别和分析期间应有明确状态提示。
- 目标解析、状态识别、规划逻辑与知识资料的准确性需要通过实际案例验证，不将未经验证的效果视为已达成。
- 模型输出直接展示的规则不改变知识资料完整性、状态准确性及目标解释一致性的产品要求。
- 按当前需求保持实现简洁，遵守 SOLID：职责分离、稳定契约、小接口、可替换实现，以及高层策略对抽象契约的依赖。
- 不因开源计划额外引入尚未确认的账户系统或运营功能。
- 开发遵守项目文件头、文档、注释和数据库操作约束。

## 11. 验收要点

以下为预期行为检查项，不代表功能已经通过验收。

| 场景 | 预期结果 |
| --- | --- |
| 自然语言指定结局和分队 | 解析为两个字段，经选项调整和确认后开始规划 |
| 两个目标字段均为空 | 按任意分队、任意结局通关规划 |
| 输入包含目标结构以外的要求 | 明确提示未纳入目标，不隐式增加目标字段 |
| 局内修改目标 | 通过选项确认后重新分析，分析期间暂停推荐 |
| 指定分队与识别结果不符 | 暂停推荐，允许重新扫描或修改目标 |
| 当前楼层地图不完整 | 提示展示缺失区域，补全及分析期间暂停推荐 |
| 完整地图已获取 | 评估整体路径，允许推荐止于需要重新判断的节点 |
| 下一节点存在接近的候选方案 | 提供备选并解释差异，否则明确推荐一条路径 |
| 战斗正在进行 | 不持续分析战斗操作，结束后读取整体变化 |
| 用户询问事件选项差异 | 比较目的、收益、风险及目标影响，不代替选择 |
| 资源不符或关键信息不足 | 暂停推荐，提示展示资源重新扫描 |
| 明确补充已发生的事件事实 | 直接更新本局记录并重新分析 |
| 提问使用假设条件 | 不修改实际记录 |
| 目标确定无法达成 | 说明原因并等待用户决定，不自动变更目标 |
| 未录入账号干员资料 | 使用约定默认资料，不强制录入 |
| 重新扫描部分干员 | 只更新识别内容，保留其他资料 |
| 局内尝试修改风险偏好 | 保持本局锁定的档位 |
| 中途接入 | 手动开始记录，提示扫描，不推定不可见历史事实 |
| 应用关闭后重启 | 保留记录，重新扫描校验后恢复推荐 |
| 查看历史对局 | 显示最新目标与最新局内状态 |
| AI 服务连续失败 | 最多重试 5 次，仍失败则暂停并显示原因 |
| 更新知识资料 | 无需发布应用功能版本即可维护游戏内容资料 |
